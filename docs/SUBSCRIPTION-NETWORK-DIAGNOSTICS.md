# 订阅指定代理与详细诊断导出

更新日期：2026-10-13。状态：实施中，尚未接入生产流程，未完成验收或发布。

## 1. 用户要求与范围

1. 订阅添加、替换和更新支持指定下载代理。
2. 优化日志导出，能够定位网络请求在哪一阶段失败，并保留重启前的排查信息。

复用现有 Electron、Node.js、Mihomo、IPC 和本地 API，不编译或更换内核。订阅下载线路只控制获取订阅的请求，不改变实例分配的节点、网页代理、系统 DNS、系统路由或 Clash 设置。节点导入后的连通性检测是另一流程，不能把下载成功作为节点可用的证明。

## 3. 已知行为与证据边界

- 当前订阅下载使用 Node HTTP/HTTPS，先校验 DNS 返回地址，再固定一个通过校验的公网 IP 连接；不是随当前实例浏览器代理下载。
- 默认全过程超时 20 秒、最大内容 2 MB、最多 3 次重定向；证书校验开启，HTTPS 不允许降级到 HTTP。失败不覆盖原订阅源。
- 系统网络可能被宿主 VPN/TUN 接管，因此界面不能将“系统网络”标为“直连”。
- 本机测试曾出现 TLS 校验通过后连接重置；同一请求经某个运行实例代理成功。固定同一服务器 IP 的测试也观察到线路差异。后续原下载器又成功，说明网络状态会变化，不能认定开 VPN 必定失败。
- 本机 Clash 连接盘点曾显示固定 IP 请求缺少域名信息，命中兜底规则。该观察不代表所有 Clash 配置或用户设备均如此。
- 其他设备诊断包分别出现订阅超时、解析到非公网地址被拒绝、节点检测 DNS 失败和连接重置。缺少实际解析结果和原始错误，不能用本机证据替其确定根因。
- 常见 Fake-IP 段 `198.18.0.0/15` 已有公网复核流程；不能将所有非公网地址拒绝都归为 Fake-IP 不兼容。

不在文档、测试夹具或提交中保存真实订阅链接、令牌、代理账号和其他用户的配置。

## 4. 指定代理的目标设计

### 界面

- 在订阅添加/编辑窗口增加“下载网络”：系统网络（默认）、指定运行中的代理实例。
- 选项显示实例名称和可用状态，不让用户猜本地端口。
- 订阅源保存所选实例 ID；单项更新及全部更新沿用各自保存的选择。
- 编辑时不泄露旧链接。只改名称保持原线路；更换线路与替换订阅分别有明确行为。
- 选中实例停止、删除、改为直连或代理不可用时，显示失败原因；保留订阅内容和用户选择，不静默切回系统网络或另一实例。
- 请求期间禁用相关按钮、输入框和选择框；成功后读取磁盘与快照验证，失败保持输入可重试。

### 后端与 API

拟增加字段 `downloadProxyInstanceId`，供 `library-save` 使用；这是设计字段，当前 IPC 尚不支持。

- 旧数据没有字段时使用系统网络。
- 建议采用三种明确语义：省略字段沿用保存值、空字符串明确选择系统网络、实例 ID 指定代理。校验必须在提交前完成，禁止未知值被当成默认。
- 外部 API 只提交实例 ID，不接受任意代理地址、端口或下载器内部选项。
- 主进程根据当前运行状态获取实际回环端口，每次请求重新获取，不能持久化临时端口。
- 代理实例必须正在运行、属于代理模式且内核存活；下载中实例停止应导致失败，无其他线路回退。
- HTTP 和 HTTPS 都要支持；HTTPS 通过隧道使用原域名做 TLS 身份校验。保持压缩、内容上限、重定向、总超时和原数据保留规则。
- 每次重定向重新校验目标，不能以指定代理为理由绕过内网、回环、元数据地址和 DNS 重绑定保护。

### 需要明确处理的取舍

目前隧道草稿连接经过校验的公网 IP，保留 TLS 的域名身份，但不等于恢复宿主 Clash 的域名分流。若改为让代理解析域名，要重新证明目标地址校验及 DNS 重绑定保护有效，不能简单删除公网校验。本功能首先提供可明确选择的下载线路，不承诺绕过宿主 TUN、自动找出可用出口或消除所有节点 DNS 问题。

## 5. 详细诊断导出目标

### 当前导出区别

| 入口 | 当前内容 |
| --- | --- |
| 导出全部日志 | 仅最近最多 1000 条操作记录；名称不能准确表达覆盖范围 |
| 导出诊断包 | 版本、系统、实例概要、节点网络模式、操作记录、本次标准输出和错误输出 |

当前调试输出在每次启动初始化，旧网络阶段也没有采集。重启后导出不会自动补回过去未记录的信息。

### 目标内容

以“导出详细诊断包”作为反馈入口；原操作记录导出需明确命名和覆盖范围，不再让用户把它误认为全部运行资料。历史 API 的导出动作保持兼容，具体文件格式变化需说明。

| 分类 | 必须采集 |
| --- | --- |
| 应用与环境 | 应用/Electron/系统版本、架构、运行时间、采集开始时间、记录上限与截断情况 |
| 订阅操作 | 任务 ID、来源 ID、指定实例 ID、网络模式、开始/结束时间、成功/失败及节点数量 |
| DNS | 域名、系统解析结果、地址族、公网/Fake-IP 判定、是否公网复核、复核结果、具体错误码 |
| 连接 | 实际目标地址和端口、回环代理端口、TCP 建立耗时、隧道状态及错误码 |
| TLS | 握手阶段、校验结果、协议与证书错误码，不导出请求凭据 |
| HTTP/内容 | 状态码、重定向次数与目标域名、编码、接收字节、解压字节、首响应与总耗时、解析结果 |
| 节点检测 | 任务/节点标识、DNS/路由模式、检测目标域名、备用目标尝试、内核生命周期、分类和提取出的失败字段 |
| 异常 | 超时所属阶段、取消、代理停止、内核退出、日志写盘/读取失败、任务未完成 |

错误必须保留来源：真实系统错误码与内核文本推导出的分类码分开表示。不能把旧的 `lookup ...` 分类提示当作原始根因，也不能从“连接重置”推断是服务器封禁。

### 留存与隐私

- 草稿使用实际用户数据目录下的 `network-trace.json`，不写死 `%APPDATA%` 名称或项目安装路径。
- 当前草稿容量：最近 300 个任务，每任务最多 160 个阶段；读取文件上限 12 MB。接入前验证容量、运行中任务保留和异常恢复。
- 正常退出刷盘；异常退出后未完成任务标记为中断。诊断包明确记录缺失、截断、采集时间范围和写盘失败，不伪造完整记录。
- 允许必要的服务器域名、目标地址、端口、任务关联信息；不导出订阅 URL 路径/查询参数、请求响应正文、Authorization、Cookie、Session、节点密码、用户备注或网页内容。
- 不原样持久化 Mihomo 输出或异常堆栈；用结构化白名单提取可用字段。对异常消息、解析失败文本和历史文件再做脱敏。
- 导出前提示诊断包会含网络域名/IP。不得将用户凭据当作“超级详细”的一部分。

## 6. 后续实施顺序

1. 审查两个草稿的参数、超时、取消、证书及安全边界，再完成 HTTP/HTTPS 下载接线。
2. 在 Library 中事务性保存下载线路，在 Controller 中初始化网络详情；IPC 只接收已校验的实例 ID。
3. 完成添加/编辑和更新入口，不只改弹窗外观；API 与界面使用同一流程。
4. 在订阅 DNS、下载器、节点准备、检测、Mihomo 生命周期中记录关联阶段；保留细节至退出与重启。
5. 升级诊断包和导出文案，说明内容、上限、脱敏与缺失情况。
6. 完成下述验收，再更新此文档、交付状态和实际使用说明。未验收前不写 Release 已支持。

## 7. 必须通过的验收

- 系统网络与指定代理：真实 HTTP/HTTPS 下载、压缩、重定向、解析、保存、单项/全部更新与重启后的线路恢复。
- 异常：代理停止/删除/直连/端口失效、隧道拒绝、TLS 错误、超时/取消、大响应、无效内容；旧源不变且没有线路回退。
- 安全：私网 URL、DNS 混合返回、重绑定、重定向私网、HTTPS 降级全部被拒绝；调用者不能从 IPC 注入内部测试参数。
- 日志：DNS 失败、超时各阶段、连接重置、节点错误有来源和任务关联；重启后仍能导出前次详情，敏感字段测试不出现凭据。
- 真实界面：两种主题、窗口尺寸、停止实例选项、忙碌状态和明确失败提示；用户原实例、节点和系统设置保持不变。
- 导出文件：真实生成、JSON 可读取、结构/数量/时间范围正确，取消不写入，保存失败有说明。
