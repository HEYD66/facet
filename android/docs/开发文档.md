# 千面 Android 开发文档

更新：2026-10-16。配套 [交接说明](交接说明.md)。本文路径均相对**交接包或原仓库根目录**，不要写死原开发机目录。

## 1. 技术栈与入口

| 部分 | 入口 / 技术 |
| --- | --- |
| 项目 | `android/settings.gradle`、`build.gradle`；独立 Android 工程 |
| 应用 | `app/src/main/AndroidManifest.xml`；Java 17；无 Electron 依赖 |
| 初始化 | `FacetApplication.java`，按进程初始化 WebView 数据目录 |
| 主页 | `MainActivity.java`，进入固定双实例 |
| 浏览界面 | `BrowserActivity.java`；两个 Profile Activity 仅提供 profile 编号 |
| 节点解析 | `NodeParser.java`，JSON / 安全 YAML / 分享链接 |
| 订阅下载 | `SubscriptionDownload.java`，显式网络选择、大小和跳转限制 |
| 内核管理 | `CoreEngine.java`，独立进程、运行配置、就绪与退出管理 |
| 调试测试 | `app/src/debug/`，正式源集不包含测试接收器 |
| 构建准备 | `setup-core.cjs`、`core-artifact.json` |
| 自动验收 | `app/src/test/` 和 `android/tests/` |

表中 Java、Manifest 路径基于 `android/`；Java 文件统一在 `app/src/main/java/com/facet/browser/prototype/`。

## 2. 进程与网络架构

```text
主进程 MainActivity（禁止初始化 WebView）
  ├─ :profile1 → suffix profile1 → WebView 1 → 本机随机代理端口 → Mihomo 1 → 所选节点
  └─ :profile2 → suffix profile2 → WebView 2 → 本机随机代理端口 → Mihomo 2 → 所选节点
```

用户也可选择手动 HTTP/SOCKS5 代理或明确使用系统网络。`ProxyController` 是进程级设置，因此不能在同一进程放两个需要不同网络的实例。

网络启用顺序（`applyProxy`）：

1. `ready=false`，停止加载，`setBlockNetworkLoads(true)`；增加 generation 序号。
2. 检查 WebView 是否支持 `PROXY_OVERRIDE`；指定代理不支持时保持阻断。
3. 在单线程执行器停止旧内核；需要节点时生成新配置、启动并等待就绪。
4. 主线程设置或清除 WebView 代理，等待回调。
5. 仅当前 generation 且 Activity 未销毁时解除阻断并导航。

内核启动并非只有端口检查：核对授权 `/version` 为 `v1.19.31`，再确认代理端口可连接。每个 profile 进程中的静态 `CoreEngine.owner` 串行管理实例内核所有权。旧 Activity 的异步 stop 不能结束新所有者。启动时读取 PID 标记并核对 `/proc/PID/cmdline` 的完整二进制和配置路径，避免误杀其他进程。

随机端口探测与实际绑定之间仍存在竞争；当前仅在识别到端口占用时最多重试 3 轮。需要压力测试才能扩大并发承诺。内核意外退出回调只阻止该 WebView；未实现自动重启策略。

## 3. 数据模型与隐私

手机应用私有目录下：

| 文件 | 用途 | 是否敏感 |
| --- | --- | --- |
| `shared_prefs/profileN.xml` | `proxy`、`url`、`useCore`、`nodeJson`、`nodeName` | 是，网址和所选节点快照可能含凭据 |
| `files/profileN-nodes.json` | 该实例节点数组，含协议白名单字段 | 是，未额外加密 |
| `files/core-profileN/runtime.json` | 本次内核配置、端口、随机 secret、节点 | 是；正常停止清理，异常时可能残留 |
| `files/core-profileN/pid` | 上次启动的 PID 标记 | 内部管理数据 |
| `files/core-profileN/diagnostic.txt` | 当前内核对象最近 100 条分类阶段记录 | 已限制内容，不是完整调试日志 |
| WebView suffix 目录 | Cookie、网站存储、缓存等 | 是，不应导出分享 |

`CoreEngine.write` 使用 `AtomicFile` 写节点与配置。SharedPreferences 的 apply 和 WebView DOM 存储写盘仍是异步的。当前没有数据 schemaVersion、迁移器、备份恢复或用户重置功能。

新增保存字段时必须考虑已有配置、失败中断和降级。诊断只记录固定类别，禁止输出完整节点 JSON、URL 查询串、原始内核输出或控制 secret。Manifest `allowBackup=false`，不能把系统自动备份当作已实现的恢复方案。

## 4. 节点导入与订阅

`NodeParser.parse` 接受受限内容并返回节点 JSON；只允许已定义协议与传输参数。YAML 使用 SafeConstructor，拒绝重复键和可执行类型。`validate` 同样在启动前执行，节点统一改名为 `facet-upstream`。

内核设置由应用生成：回环 mixed/controller，`allow-lan=false`，`dns.enable=false`，`tun.enable=false`，规则仅 `MATCH,facet-upstream`。订阅顶层不能替换这些配置。解析器扩展时应同时补充正常参数、无效端口、未知字段、嵌套配置、大小和危险插件拒绝测试。

下载器使用显式 `Proxy`：系统网络为 `NO_PROXY`，当前实例网络从已生效的 `activeProxy` 构造。连接超时 10 秒、读超时 15 秒，最多跟随 5 次跳转，不接受 HTTPS 降级、URL 用户信息和片段，要求 HTTP 200；gzip 解压内容限制 2 MiB。默认 TLS 验证保留，没有忽略证书的开关。

限制是内容长度和单次读超时，**不是严格的全请求墙钟超时**；持续缓慢返回的服务可能占用工作线程更久。取消不立即关闭已发送连接，只通过 AtomicInteger 阻止尚未提交的数据入库。节点库总量 500 条，未实现去重、周期更新和 URL 持久化。

## 5. 构建环境与命令

已验证组合：Windows / JDK 21（源码目标 17）/ Gradle 8.13 / AGP 8.13.2 / compileSdk 36 / build-tools 35.0.0 / Node 22.12+。主依赖 AndroidX WebKit 1.9.0、SnakeYAML 2.4；JVM 测试依赖 JUnit 4.13.2、org.json 20240303。SDK 29 的 UiAutomator 库仅用于编译测试输入工具，应用编译用 SDK 36。

工程没有 Gradle Wrapper，需提供自己的 Gradle 8.13。以下盘符仅为示例，按实际机器设置；在交接包根目录执行：

```powershell
$sdk = 'D:\Android\Sdk'
$jdk = 'D:\Android-studio\jbr'
$cache = 'D:\Android\GradleCache'
$gradle = Join-Path $cache 'distributions\gradle-8.13\bin\gradle.bat'
$env:JAVA_HOME = $jdk
$env:ANDROID_HOME = $sdk
$env:ANDROID_USER_HOME = Join-Path (Split-Path $sdk -Parent) 'UserHome'
$env:ANDROID_SDK_HOME = $null
$env:GRADLE_USER_HOME = $cache

& .\android\build.ps1 -SdkPath $sdk -JavaPath $jdk -GradleCache $cache -GradleExecutable $gradle
& $gradle -p .\android testDebugUnitTest lintDebug processReleaseMainManifest --no-daemon --console=plain
& .\android\tests\verify-apk.ps1
```

`build.ps1` 自己暂存并恢复进程环境；上面为单测手工设置的环境仅作用于当前终端。SDK 需要许可与组件已就绪；工具链不在交接包中。不要安装新组件到未知的旧 SDK 目录。

`setup-core.cjs` 用 Node 内置模块和 `curl.exe`，先校验包内缓存再解包官方内核。缺失或不匹配时尝试下载，下载完成仍核对锁定 SHA256。资源同级路径是工程约定而非机器绝对路径。

产物：`android/app/build/outputs/apk/debug/app-debug.apk`。本机新生成调试签名可能与交付 APK 不同，字节哈希也不应被当作确定性重建承诺。当前 APK 不包含发布签名配置。

中文路径注意：工程允许 AGP 路径检查；JUnit 将编译后类路径复制到 Gradle 缓存 ASCII 路径后运行。缓存根目录也应使用不含中文的路径。该兼容措施不等于所有未来 NDK 插件已支持中文路径。

## 6. 内核与许可资源

Android 锁定信息是 `android/core-artifact.json`。构建准备会生成：

```text
app/src/main/jniLibs/arm64-v8a/libfacet_mihomo.so
app/src/main/assets/mihomo/LICENSE
app/src/main/assets/mihomo/ARTIFACT.json
app/src/main/assets/mihomo/source.tgz
```

`useLegacyPackaging=true` 将二进制提取到安装 nativeLibraryDir；保留原字节，避免 strip 破坏文件。`.so` 文件名用于 APK 提取，它实际是独立 ELF ARM64 可执行程序，不是 JNI 接口库。`source.tgz` 是对应版本原始源码压缩文件；`verify-apk.ps1` 从最终 APK 中读取并核对 4 份资源哈希。

升级时：同时更新下载 URL/摘要、Android ABI、`CoreEngine` 的就绪版本常量、下载器 User-Agent（如适用）、对应源码及许可；重新执行单测、签名/资源校验和真机 HTTP/SS/异常退出测试。不要只替换可执行文件。`resources/mihomo/mihomo.exe` 是 PC 端 SS 测试服务器，不进 Android APK。

## 7. 安装与真机测试

先校验交付 APK，按设备选择安装。下面的设备 ID 从 `adb devices -l` 取得，不要复制别人的序列号：

```powershell
$env:FACET_ADB = Join-Path $sdk 'platform-tools\adb.exe'
& $env:FACET_ADB devices -l
$env:FACET_DEVICE = '<本次测试设备ID>'
& $env:FACET_ADB -s $env:FACET_DEVICE install -r .\artifacts\Facet-Android-0.2.0-prototype-arm64.apk

& .\android\tests\build-input-helper.ps1 -SdkPath $sdk -JavaPath $jdk -Platform android-29 -BuildTools 35.0.0
node .\android\tests\device-smoke.cjs
node .\android\tests\core-device.cjs
```

用新构建替换安装命令中的 APK 路径。脚本需要 debug APK 的 run-as/WebView 调试能力、手机解锁、ADB 已授权、允许 USB 安装。多个设备必须指定 FACET_DEVICE。手机拒绝安装时等待用户允许，不绕过安全设置。

测试脚本为 Node 内置模块，不依赖桌面 npm 安装或 Playwright。通过 ADB reverse/forward 访问本机测试源站、HTTP 代理、真实 Mihomo Shadowsocks 入站；通过 WebView 页面 WebSocket CDP 操作。运行后输出临时报告目录，并清理本次映射。

**会影响原型数据的测试边界：** `device-smoke.cjs` 会修改两实例代理/网址，写测试站点数据并强制停止原型；不恢复所有网站存储。`core-device.cjs` 保存并恢复偏好和节点库，但不是全应用快照。两者都不能作为正式用户数据上的无损测试。

输入辅助类通过 UiAutomator 的 ACTION_SET_TEXT 填写应用原生输入框，替代易受输入法影响的 adb input text。异常内核退出通过 debug-only `CoreCrashTestReceiver` 测，DUMP 权限保护且验证目标命令行；正式合并清单必须排除它。当前没有 Android Instrumentation Runner 配置。

## 8. 验证与常见故障

| 现象 | 先检查 |
| --- | --- |
| 安装失败 / 被用户取消 | ADB 返回码、设备安装确认、USB 安装、ABI、签名；不要先卸载 |
| 新机器 cannot install update | 新 debug 签名与旧包不同；保留旧数据，规划签名/迁移 |
| 代理无效 / 阻止页面加载 | 当前 WebView 是否支持 PROXY_OVERRIDE；状态是否等待回调 |
| 内核不能执行 | ARM64、APK 提取与 nativeLibraryDir；不要迁回可写目录执行 |
| 内核启动失败 | 分类阶段记录、版本就绪常量、节点参数、端口占用；不输出凭据 |
| 节点能解析但不能连接 | 协议/传输兼容、手机网络、证书、上游可达性；解析测试不能证明连通 |
| 下载订阅失败 | 选择的下载网络、HTTP 状态、TLS、跳转和大小；系统网络仍受 VPN 影响 |
| JVM 测试 ClassNotFound | Gradle 缓存路径字符、测试类 staging；不要搬走整个原仓库 |
| 无 WebView CDP target | 必须 debug 包、目标实例已打开，等待 target 创建；不用桌面 context API |
| 后台实例消失 | Android 生命周期、进程回收；当前没有前台服务保活设计 |

判断“成功”应同时检查页面实际内容、上游请求、保存数据、重启恢复、失败路径与最终 APK；HTTP 200、端口存在和 UI 提示都不能单独证明功能完成。

## 9. 后续改动与交付规则

- 只改 Android 相关代码；桌面端源码、数据与现有流程保持独立。
- 改数据模型、进程结构、网络或内核前保留 Git 检查点及必要数据备份，备份不得进入交接包/Git。
- 回归最低要求：构建、10 项现有 JVM 测试、Lint、APK 资源/签名、双实例隔离和网络失败实测；有新行为应新增对应有效测试。
- 每次交付保存源码快照、APK 摘要、实际设备/内核/WebView 版本与报告；不写设备序列号、订阅凭据。
- 交接包根目录的校验脚本只检查文件完整性；它不证明签名归属、源代码安全或对新设备的兼容性。
